MazenOS / Phone setup

Connect your phone.

MacroDroid enforces the phone overlay. The Worker returns decisions and never directly controls Android.

Before you begin

Create a phone token in MazenOS Settings. Store the Worker base URL and token in MacroDroid’s own variables. Do not store your master password or AI keys in MacroDroid.

Every request uses this header:

Authorization: Bearer YOUR_PHONE_TOKEN

For POST requests, also set:

Content-Type: application/json

Never send credentials in URL query parameters. Token replacement immediately invalidates the previous phone credential.

1. Phone status

Create a regular-interval trigger every 5–15 minutes. Send an HTTP GET to:

/status

Extract the JSON boolean device_unlocked. If it is false, enable your persistent focus overlay; if true, remove that overlay.

{"device_unlocked":true,"reason":"clear"}

The reason can also be overdue_task, unrelated_media, recovery, rest or leisure. Sickness, rest windows, scheduled leisure and Fridays clear device friction. There is no password or key information in this response.

Only act on a successful HTTP 200 with a valid boolean. On a network/auth/server error, do not reinterpret it as proof completion. Keep your chosen safe recovery behavior and surface an Android notification. Polling means task completion may take until the next poll to remove an overlay; you can add an explicit manual refresh trigger.

Keep emergency calls, authentication, MazenOS proof upload and a manual MacroDroid recovery action reachable. Verify the unlock path before enabling the blocking macro.

2. Bank SMS

Create an SMS-received trigger limited to your bank’s actual sender(s). Exclude OTP and verification messages before making a request. POST to:

/api/budget/sms

Use MacroDroid’s JSON escaping or a JSON-building action for message text. Raw string concatenation breaks when an SMS contains quotes or newlines.

{
  "message_id":"A_STABLE_SMS_ID",
  "received_at":"2026-10-21T12:00:00+03:00",
  "sms":"Purchase SAR 18.50 card **1234 at Coffee Shop\nBalance SAR 81.50"
}

Use a stable ID from the SMS, or a value you generate once for that message and reuse on retries. If no ID is supplied, the exact SMS text is hashed for deduplication. An exact retry returns duplicate:true.

Recognized examples include English purchase/payment/deposit and Arabic شراء/سحب/إيداع card alerts with a four-digit card reference and SAR amount. Arabic-Indic digits are normalized. Unrecognized or ambiguous templates return HTTP 422 and add nothing. Log the expense manually and adapt parseBankSMS in worker-tools.js after inspecting your bank’s redacted format.

The server does not store the raw SMS. This does not grant MacroDroid any ability to read your ledger, diary, keys or chat.

3. NewPipe video title

Create a notification-received or UI-reading trigger limited to NewPipe. Extract the current video title and POST:

/api/audit/media
{"title":"The actual current video title"}

The server chooses the highest-priority active video task. An optional task_id targets a specific task if you have stored its ID in your macro. For a simple single active task, omit it.

A relevant title creates a one-hour, task-version-bound check. An unrelated title creates a 15-minute media lock. A failed service request never produces an accepted video check. On a successful response, apply device_unlocked immediately instead of waiting for the next poll.

This checks title relevance only. It cannot prove viewing time or validate actual video content. You still upload photo/PDF proof from the task page; an accepted audit is what completes the task.

4. Optional energy sync

Once your Android-side bridge can read your Samsung Health energy score, POST:

/api/health/sync
{"energy_score":75}

Only whole numbers 0–100 are accepted. The score applies to the current health day, resetting at 03:00 Riyadh. Samsung Health extraction itself is not bundled: availability depends on the phone’s supported export/integration or permitted UI automation. Until that is configured, use the energy field in Health.

Test in this order

  1. Keep the overlay disabled and confirm /status returns a valid response.
  2. Create a genuine overdue P1 task outside a rest/leisure window and verify false.
  3. Turn on Recovery in Health and verify true. Turn it off afterward.
  4. Submit an unrelated title and check the temporary lock; submit a relevant title to clear it.
  5. Forward one redacted bank alert twice; confirm one ledger entry.
  6. Enable the overlay only after the emergency and manual recovery routes work.

Android background and accessibility permissions must be granted on your actual phone. This project does not include a universal imported MacroDroid macro because action IDs, package names, notification formats and device restrictions differ.
